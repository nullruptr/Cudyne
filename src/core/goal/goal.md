# Goal

指定した期間に指定した時刻目標を達成したのか、達成していないのかを判定する。
判定式は、./goal_eval.hpp に記述している。

## Goal の機能

- Name: 名前を設定できる
- Category / ToDo: カテゴリか、ToDo に対して、目標を設定できる。
- Period Type: 日 / 週 / 月 / 任意周期 / 未定義（時間のみ達成できればOK) / Rolling（達成時刻を起点に繰り返す） 別に目標を設定できる。
- Every n Days: 任意周期の時、何日周期で設定できるのか定義する。Rolling のときは、n 日以内の n として使う。
- 窓ごとの目標時間の例外設定: ある週や月だけ、Target Time を変更(0 で免除)できる。「窓ごとの例外設定」を参照。
- Start Time: いつから開始するのかを設定する。
- End Time: 終了日、終了時刻を設定する。
- Target Time: 目標時間を設定する。
- note: メモ

### 前提となる制約条件等

- 選択可能な最大時間をとる。すなわち、例えば、Target Time で、月を選択した場合は、744h (31日)前提で計算する。
30 日の月では、達成しえない可能性があるが、これは、Goal ダイアログで別途警告処理を追加する。
- 週、月等を選択したとき、Start Time が選択した期間の一番最初(暦期間)で計算をする。
ただし、既存のDBの仕様の影響で、Monthly で、10/15 を選択していたとしても、集計は、10/01 00:00 からになりますと、英語でStaticText を表示するようにする。
- Month / Weekly / Daily で、途中に EndTime があった時、その時間で集計を終了する。
つまり、Month のとき、10/15 で終了したとしても、10/15 日以内に、月目標を達成しないといけない。週も同様。
- 時差による判定処理は、その地域別に再計算する。
records、start_time、end_time は UTC で保存されている。
境界(0 時、月曜、1 日)は、評価する時点の、端末のローカル時刻で決める。
保存はせず、毎回計算するので、タイムゾーンを変えると窓の位置も変わる。
- End 後の未達成か、達成していないかの判定については、セルの色を変えて表示し対応する。
また、達成可否を確認できる画面も別途用意する。
- 無効(is_active = 0)で、かつ End を過ぎている -> 無効
- Start 前で、かつ実績が目標を超えている(窓の頭から数える設計なので起こり得る) -> 達成
ただし、Start が「今の窓」に含まれる場合に限る。Start が今の窓より先にあるときは、実績が目標を超えていても 開始前 とする。
- End を過ぎていて、End までの窓で目標を達成していた -> 終了済(達成)。達成していなければ 終了済(未達)。
判定するのは、End を含む最後の窓だけとする(たとえば Daily なら、End の日の窓のみ)。それ以前の窓の達成率は、照会画面で確認する。

| 期間 | 窓 |
|---|---|
| Daily | 0 時から翌 0 時 |
| Weekly | 月曜 0 時から翌月曜 0 時 |
| Monthly | 1 日 0 時から翌月 1 日 0 時 |
| Every n Days | Start の日を基準に n 日ごと |
| Undefined (End なし) | Start Time 以降、目標時間を達成したか否かを判定するだけ| 
| Undefined (End あり) | Start Time ~ End Time の達成判定で達成出来ているかを判定する| 
| Rolling | 現在サイクルの開始時刻から n 日以内。達成したら、達成した record の終了時刻を起点に次のサイクルを始める |

### 色を付ける条件

| 状態 | 条件 | 色の例 |
|---|---|---|
| 達成 | 残り ≤ 0 | 緑 |
| 余裕あり | 猶予が十分ある | なし |
| 急ぎ | 猶予が閾値以下（閾値 = min(24 時間, max(1 時間, 残り × 0.5))） | 黄 |
| 遅れ(Behind) | 達成率 < 経過率 - 許容幅(5pt)。急ぎより薄い橙 | 橙 |
| 未達確定 | 猶予 < 0 | 赤 |
| 開始前 | `start_time` 前 | 水 |
| 終了済（達成） | `end_time` 後で，期間内に達成していた | 緑系（濃淡で「進行中の達成」と区別） |
| 終了済（未達） | `end_time` 後で，達成していなかった | 赤系 |
| 無効 | `is_active = 0` | 灰(行全体) |

wxDataViewCtrl に対し、どこにどのように色付けするのか(セル中か、行に対してか)についてはまだ決めていない。
色は、apptheme.hpp にまとめる予定。
色だけではわかりにくいので、状態については、一番左のセルに状態を表示するようにする予定。
色は、一番左の状態のセルだけ色を付けて、無効（灰色）は、全セルにつける。

### Rolling（達成起点リピート）

n 日以内に目標を達成し、達成したらその達成時刻を起点に、もう一度 n 日以内の窓を始める。

- サイクルの開始時刻 S は、最初は Start Time。以降は、前サイクルの達成時刻 T。
- 現在の窓は `[S, S + n 日)`。n 日は暦日(ローカル時刻の日付に n を足す)で数える。
- 達成時刻 T = そのサイクルの目標に到達した record の終了時刻。
  - 超過分は捨てる。次サイクルの集計は T 以降のみで、到達した record の超過分は次サイクルに入らない。
  - 目標を 1 秒にして、「やったかどうか」のフラグとして使える。
- n 日を過ぎても窓は閉じない。未達のまま超過状態(未達確定)が続き、達成した時刻 T から次サイクルが始まる。
- 記録中の record で目標に届いた間は、表示上は達成とするが、T は record が終了するまで確定しない。
- 現在のサイクルは `goal_window` テーブル(後述)で表す。Start Time から `achieved_at` をたどった先が、現在のサイクルの開始。
- 達成時刻の確定は、評価のたびに行う(Goal 一覧の読み込み時など)。終了済みの record の累計が目標に届いていれば `achieved_at` を保存し、次のサイクルに進む。
  記録中の record は数えない(終了して初めて T が決まる)。
- 保存した達成時刻は、後から record を編集・削除しても変わらない。
- `period_type`、`period_n`、`start_time` を変更すると、起点が変わるので、保存済みのサイクルは消えて Start Time から作り直す。
- 実績は S から min(今, 窓の終点) までの records を合算する。S をまたぐ record は重なる部分のみ数える。
- 経過率(Behind)は `(今 - S) / (窓の終点 - S)` で計算する(窓の終点 = S + n 日)。n 日を過ぎたら 100% とする。
- End Time は他の Period Type と同じく、サイクルを打ち切る。

### 窓ごとの目標時間の例外設定

ある窓だけ目標時間を変えたい(海外研修で月 60h を 30h に免除するなど)。

- 管理テーブル `goal_window`(名前は仮)に保存する。1 テーブルを Rolling のサイクル管理と共用する。

| 列 | 内容 |
|---|---|
| `goal_id` | goal.id |
| `window_key` | 窓の識別子。通常型はローカル暦の窓開始日(例: `2026-10-01`)、Rolling はサイクル開始時刻(UTC) |
| `target_override` | その窓だけの目標(秒)。NULL = 例外なし。0 = 免除 |
| `achieved_at` | Rolling のみ。達成時刻 T(UTC)。NULL = 未達 |
| `memo` | メモ |

- 例外設定は、Rolling と Undefined では使えない(Rolling は先のサイクルの開始が決まらず、Undefined は窓が 1 つしかないため)。
  Daily / Weekly / Monthly / Every n Days で使える。
- 設定は Goal 一覧の「Overrides」ボタンから、ダイアログで行う。
  - 設定済みの窓を表で表示する(窓の範囲 / 通常の目標 / 例外の目標 / メモ)。
  - 追加は、日付を選ぶと、その日を含む窓が自動で決まる。窓の範囲を表示する。
  - 選べない日: Start の窓より前、End 以降、Every n Days で最初の窓より前。
  - 目標の上限は、その窓の長さ。
  - 最初の例外を作るときに、Period Type などが変更できなくなることを確認する。
- Goal 一覧の Target 列は、例外のある窓では `30:00:00 (60:00:00)` のように、通常の目標を添える。
- 目標 0(免除)の窓は、状態が「達成」になる。
- `(goal_id, window_key)` は UNIQUE。
- 通常型の `window_key` を暦日にするのは、窓の境界を端末のローカル時刻で毎回計算する仕様のため。epoch で保存すると、タイムゾーンを変えたときにずれる。
- 過去の窓にも設定できる。照会画面の達成判定にも使う。
- 評価では、窓が決まった後に `target_seconds` をこの値で差し替える。0 のときは達成とする。
- 例外設定が 1 件以上ある goal(過去・現在を問わない)は、`period_type`、`period_n`、`start_time` を変更できない。
  窓の位置がずれて、例外設定が別の窓を指すバグを防ぐため。例外設定をすべて削除すれば変更できる。
  ダイアログで無効にするだけでなく、DB 層でも拒否する。
- goal を削除するときは、同じトランザクションで `goal_window` の行も削除する。
- goal.id は `AUTOINCREMENT` のため、削除した ID は欠番となり、再利用されない。

### 親フォルダに対して制約条件があった場合

この時は、親の条件下の元で制約条件を計算する。
例えば、フォルダに対して、Monthly を設定された場合、カテゴリが設定できる条件は、Monthly / Weekly / Daily
Weekly であれば、Weekly / Daily のみなど。
計算が複雑になるので、具体的な処理方式はまだ検討中。
時間が、親 <= 子 のとき、親は自動的に達成なわけなので、この処理は必要なのかがまだわからない。
いったん保留。

### 自カテゴリに複数条件があった場合

~基本的に、同じ Period Type を設定できないようにする。例えば、Monthly と Monthly は共存できない。~
~必ず、Monthly / Weekly / Daily と分ける。~
~また、Monthly / Weekly / Daily のいずれかがカテゴリに作成されていた時、Every n Days / Undefined は設定できないようにする。~
やっぱり、これは制約を設けず、自分で決めてもらうようにする。
自由度が高い方が良いので。

## 計算処理方式

### 入力と出力

- 入力: goal(GoalSpec)、評価したい時刻 `at`、現在時刻 `now`、窓内の実績(秒)
- 出力: 状態、窓の始点・終点、実績、残り、猶予
- 時刻はすべて epoch 秒(UTC)の整数で受け渡す。
- 窓の境界(0 時、月曜、1 日)は、端末のローカル時刻で決める。タイムゾーンは引数にせず、C 標準の `localtime` / `mktime` を使う。
  テストは `TZ` 環境変数を固定して行う。
- DB と wxWidgets には依存しない(実装: `goal_eval.hpp`)。

`GoalSpec` のフィールド:

| フィールド | 内容 |
|---|---|
| `period_type` | 0:Daily, 1:Weekly, 2:Monthly, 3:EveryNDays, 4:Undefined, 5:Rolling(DB の `goal.period_type` と同じ) |
| `period_n` | EveryNDays / Rolling のときの n |
| `cycle_start_epoch` | Rolling のみ。現在のサイクルの開始時刻。DB 側(`goal_window`)が確定して渡す |
| `target_seconds` | 期間ごとの目標(秒) |
| `start_epoch` | 開始日時 |
| `end_epoch` | 終了日時。期限なしは `kNone`(-1) |
| `is_active` | 有効 / 無効 |

### 窓の求め方(at を含む窓)

| 期間 | 窓の始点 | 窓の終点 |
|---|---|---|
| Daily | at の日の 0 時 | 翌日 0 時 |
| Weekly | at を含む週の月曜 0 時 | 翌月曜 0 時 |
| Monthly | at の月の 1 日 0 時 | 翌月 1 日 0 時 |
| Every n Days | Start の日の 0 時から n 日ごとに区切った、at を含む窓 | 始点 + n 日 |
| Undefined | Start | End(なければ終点なし) |
| Rolling | 現在のサイクルの開始時刻 | 始点 + n 日 |

- End があれば、窓の終点 = min(窓の終点, End)。
- `at` が End 以降のときは、End を含む最後の窓を返す。
- Every n Days で、`at` が Start の日の 0 時より前のときは、窓が定義できない(開始前)。
- 実績は、窓の始点から min(今, 窓の終点) までの records を合算する。窓をまたぐ record は、重なる部分だけを数える。
- 記録中の record(終了していないもの)は、今までの経過時間を実績に含める。対象は、Category ならサブツリー全体、ToDo なら紐付く record。

### 残りと猶予

- 残り = max(0, 目標 − 実績)
- 猶予 = 窓の終点 − 今 − 残り(窓の終点がなければ「-」)
- 猶予は、今から連続して稼働できることを前提とした値である(睡眠や就業時間は考慮しない)。
- 窓の終点がなければ猶予は計算できないので、達成していない限り「余裕あり」とする。
- 急ぎ: 閾値 = min(24 時間, max(1 時間, 残り × 0.5))
- 達成率 = 実績 / 目標 × 100
- 経過率 = (今 - 窓の始点) / (窓の終点 - 窓の始点) × 100
  - 窓の始点は、窓の暦上の始点(Start より前でもよい)。既存仕様どおり、窓の頭から数える。
  - 窓の終点がない場合(Undefined で End なしなど)は、経過率を計算できないので Behind の対象外。
  - 目標が 0 のときは達成なので対象外(ゼロ除算を避ける)。
- 遅れ(Behind): 達成率 < 経過率 - 許容幅。許容幅は 5pt。
  窓の開始直後は、経過率が小さいだけで警告が出ないようにするため。
  急ぎは猶予の絶対値、遅れは進捗の割合を見るので、急ぎが先に判定される。
- 表記: 状態セルに `Behind -12pt`(達成率 - 経過率)と出す。詳細には `経過 80% / 達成 55%` を出す。

### 状態の判定順

上から順に判定し、最初に条件を満たした状態を採用する。

| 順位 | 状態 | 条件 | 備考 |
|---|---|---|---|
| 1 | 無効 | `is_active = 0` | End を過ぎていても、無効とする |
| 2 | 終了済(達成) | End を過ぎており、End を含む最後の窓で残り ≤ 0 | 判定するのは最後の窓のみ(過去の窓の達成率は照会画面で確認する) |
| 2 | 終了済(未達) | End を過ぎており、End を含む最後の窓で残り > 0 | 同上 |
| 3 | 達成 | 残り ≤ 0 | Start 前でも達成とするのは、Start が「今の窓」に含まれる場合に限る(窓の頭から集計するため)。Start が今の窓より先なら、順位 4 の開始前とする |
| 4 | 開始前 | now < Start Time | 未達成のとき、または Start が今の窓より先のとき |
| 5 | 未達確定 | 猶予 < 0 | 猶予 = 0 は、今から連続稼働すれば間に合うので、未達確定にしない。Rolling は n 日を過ぎてもここに入り、窓は閉じない |
| 6 | 急ぎ | 猶予 ≤ 閾値 | 猶予 = 0 を含む。閾値は「残りと猶予」の節に従う |
| 7 | 遅れ | 達成率 < 経過率 - 5pt | 窓の終点があるときのみ |
| 8 | 余裕あり | 上記のいずれにも該当しない | 窓の終点がなく猶予が「-」のときも、ここに入る |

## 画面(Goal 一覧)の更新方式

- 1 秒ごとに、読み込み時点の実績から、残り時間・猶予・状態を再計算して表示する(DB には問い合わせない)。
  記録中の goal は、経過時間ぶん実績が増えるものとして扱うので、猶予は減らない。
- 次の場合は、DB から読み直す。
  - 窓の終点を過ぎたとき(日付が変わったときなど)
  - 30 秒経過したとき(記録の開始・終了を反映するため)
  - Refresh ボタンを押したとき
- Condition の切り替えは、読み込み済みの行を絞り込むだけで、DB には問い合わせない。
- 行の並びが変わらない更新では、選択を保つ。

## Detail

Goal について表記しているが、複数制約持てる方式にしたので、未達成件数、達成件数等を表示し、詳細は一覧ダイアログで見る方式にする。

実装:

- 対象は、Detail で選択している Category に設定された goal のみ(子カテゴリの goal は含めない)。
- 今の時点で各 goal を評価し、状態を 3 つに分類して件数を数える(Goal 一覧の Condition と同じ分類)。

| 分類 | 該当する状態 |
|---|---|
| Achieved | 達成、終了済(達成) |
| Unachieved | 余裕あり、急ぎ、未達確定、終了済(未達) |
| Invalid | 開始前、無効 |
